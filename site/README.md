# sweeploom.com

Marketing and docs site for SweepLoom, a Weavatrix product. Next.js (App
Router) + TypeScript + Tailwind CSS, exported as plain static files. No
analytics, no trackers, no cookies, no runtime requests to third parties
(fonts are bundled at build time by `next/font`).

## Stack

| Package | Version |
| --- | --- |
| next | 16.4.0 (Turbopack, `output: "export"`, `trailingSlash: true`) |
| react / react-dom | 19.3.0 |
| typescript | 7.0.2 (Next runs it through the TypeScript CLI) |
| tailwindcss / @tailwindcss/postcss | 4.3.3 |
| unified, remark-*, rehype-*, gray-matter | Markdown → HTML at build time |

Node 20.9 or newer. Versions are pinned exactly in `package.json`.

## Commands

```sh
npm install
npm run dev        # http://localhost:3000
npm run build      # static export into ./out (runs prebuild first)
npm run preview    # serve ./out on http://localhost:4321
npm run typecheck
npm run changelog  # regenerate content/changelog.json from git log
npm run deploy     # build and publish to the Hetzner host (see below)
```

`npm run build` needs network access once per clean build: `next/font`
downloads Inter, Space Grotesk and JetBrains Mono and self-hosts them.

## Layout

```text
app/                 routes (App Router). Every page is static.
  page.tsx           home
  features/ app/ mcp/ docs/ download/ blog/ about/ changelog/
                     app/ = desktop app tour, mcp/ = MCP and Codex plugin guide
  terms/ privacy/ license/ not-found.tsx
  blog/[slug]/       post pages + og.png per post
  og.png/            default 1200×630 Open Graph image (route → out/og.png)
  apple-touch-icon.png/
  rss.xml/           RSS 2.0 feed (route → out/rss.xml)
  sitemap.ts robots.ts
components/          header, footer, theme switch, code blocks, tabs, MCP chat
                     transcripts (Chat), blog copy buttons (CodeCopy), ScrollSpy, …
content/blog/*.md    blog posts (frontmatter below)
content/legal/       TERMS.md, synced from the repo root before each build
content/changelog.json  generated from git log
lib/                 site constants, product facts, blog + markdown loaders
public/              favicon.ico, icon.svg, mark.svg, mark-512.png, screenshots/
scripts/             changelog.mjs, sync-legal.mjs, favicon.mjs
```

Product facts used across pages live in `lib/content.ts` and `lib/site.ts`
(install commands, MCP snippets). They are transcribed from the repo's
`README.md` and `docs/*.md`; update them together.

## Blog posts

Add `content/blog/<slug>.md` (or `.mdx`, rendered as Markdown):

```md
---
title: "Post title"
date: "2026-10-08"
summary: "One or two sentences for the index, RSS and meta description."
tags: ["sessions", "safety"]
---

Body in GitHub-flavoured Markdown. Raw HTML is not passed through.
```

Fenced code blocks are wrapped at build time (`lib/markdown.ts`) in the same
terminal frame as the TSX `CodeBlock`, with the language and a Copy button;
`components/CodeCopy.tsx` makes the buttons work (blocks with `$ ` prompt
lines copy only the commands). Images can use `/screenshots/*.png`.

The index, post page, per-post OG image, RSS feed and sitemap pick it up on
the next build. Posts are sorted newest first.

## Terms of Use

The Terms page renders `content/legal/TERMS.md`. `npm run build` first runs
`scripts/sync-legal.mjs`, which copies `../TERMS.md` from the repository
root, so the site and the repo always say the same thing. Commit the copy
so the site still builds outside the repo. The Privacy and License pages
are written in TSX and must stay consistent with TERMS.md section 4.

## Screenshots

The home page, the desktop app tour (`/app/`) and some blog posts show these
desktop-app screenshots. All of them are redacted (names and paths blurred);
the originals are in `../docs/screenshots/`. Never add an unredacted capture.

```text
public/screenshots/overview.png         Overview
public/screenshots/sessions.png         Sessions
public/screenshots/project-output.png   Cleanup → Project output (1600×909)
public/screenshots/cleanup.png          Cleanup → iOS & Xcode
public/screenshots/projects.png         Projects (1600×1004)
public/screenshots/ai.png               AI
```

Until a file exists, a labelled app-window placeholder is rendered instead
(existence is checked at build time, so rebuild after adding them). Use
16:10 images, about 1600×1000, ideally captured in the dark theme. Pass
`frame` to `<Screenshot>` to show a shorter capture in a 16:10 frame that
continues the app's sidebar, so mixed heights line up in a grid.

## Changelog

`content/changelog.json` is committed so CI builds do not need full Git
history. Refresh it with `npm run changelog` after new commits. The
"Unreleased" notes and the release boundary (`RELEASE_HASH`) are in
`app/changelog/page.tsx`.

## Icons

`public/favicon.ico` and `public/mark-512.png` are generated by
`node scripts/favicon.mjs`, which ports the per-pixel mark from
`apps/sweeploom-gui/src/mark.rs`. `public/icon.svg` and
`components/Logo.tsx` draw the same mark as vectors.

## Deploy

The output in `out/` is plain static files with `trailingSlash: true`, so
`/about/` is `out/about/index.html` and `out/404.html` is the not-found
page. It works on any static host.

### Hetzner + nginx (sweeploom.com)

The site is served by nginx from `/var/www/sweeploom.com` on the Hetzner
host `46.225.60.104`. Cloudflare only holds DNS for the zone (no proxy, no
Worker). [`deploy/nginx.conf`](deploy/nginx.conf) is the site config and
[`scripts/deploy.sh`](scripts/deploy.sh) does everything over SSH with
`~/.ssh/hetzner-prod`:

```sh
bash scripts/deploy.sh --setup   # once: nginx, certbot, site config, first upload
npm run deploy                   # every release: build, rsync --delete, reload
bash scripts/deploy.sh --tls     # once DNS resolves: Let's Encrypt + HTTPS redirect
```

DNS records in the Cloudflare zone (DNS only, grey cloud), all live:

| Type | Name | Value |
| --- | --- | --- |
| A | `sweeploom.com` | `46.225.60.104` |
| AAAA | `sweeploom.com` | `2a01:4f8:1c1f:75e4::1` |
| A | `www` | `46.225.60.104` |
| AAAA | `www` | `2a01:4f8:1c1f:75e4::1` |

`SWEEPLOOM_HOST` and `SWEEPLOOM_SSH_KEY` override the target. `www` is
served as a second name; canonical URLs already point to the apex.

### Other static hosts (alternatives)

- **Pages:** build command `npm run build`, output directory `out`, root
  directory `site`.
- **GitHub Pages:** upload `site/out` with `actions/upload-pages-artifact`
  and add an empty `out/.nojekyll` so `_next/` is served. Serve from a custom
  domain at the root; a `/<repo>/` subpath would need `basePath`.

## Checks before publishing

- `npm run build` finishes with no errors and `out/` contains `index.html`,
  `404.html`, `rss.xml`, `sitemap.xml`, `robots.txt` and `og.png`.
- `npm run preview`, then check the home page at 360 px and 1440 px in both
  themes.
- Install commands on Home, Docs and Download match `docs/INSTALL.md`.
